# Mini SOC Environment Project Home Lab

## Objective

Acquire hands-on expertise with industry-standard SOC tools and essential tasks, including seamless log ingestion with the ELK stack, identifying brute force attacks and malware, crafting insightful alerts and dashboards in Kibana, conducting thorough investigations of command-and-control activities, and effectively integrating a ticketing system to streamline incident response.

### Skills Learned

- Learned how to draw a logical diagram connecting all VMs.
- Setup Ubuntu/Windows instances and configured software i.e. ELK, Mythic (Apollo agent), osTicket, etc. 
- Learned how to attack, detect SSH/RDP brute-force activity, and investigate malware.
- Created alerts and dashboards using Kibana.
- Setup and integrated a ticketing system to organize and respond to telemetry.

### Tools Used

- Virtual box to set up VM instances (Windows, Ubuntu, Kali Linux).
- ELK stack for log ingestion.
- Kibana for creating alerts and dashboards.
- Mythic to configure a C2 server, create malicious .exe payload, and run commands on the victim's computer.
- Kali Linux to connect to and exfiltrate files from our Window's server to our C2 server.
- Ticketing system (osTicket) to identify high-level alerts.
- Elastic EDR (Elastic Defend) to detect potential malware.

## Steps

All steps in detail can be found <a href="https://docs.google.com/document/d/1CbhM4QFlc_ufb07FR8R2i48FS9zk7CauDyG8oMh_XME/edit?tab=t.0" style="color: blue; text-decoration: underline;">here</a>

1. Set up 7 virtual machines. Windows Server 2022 (2), Ubuntu Server (4), and Kali Linux (Attacking Machine). Also configured them to all be on the same NAT network.

2. <p>Created a <a href="https://imgur.com/a/Mu4jCCq" style="color: blue; text-decoration: underline;">logical diagram</a> showing how the VMs were connected.</p>

3. Installed & configured Elasticsearch and Kibana on our ELK VM. 
   
4. Configured Windows Server to allow for RDP. 
   
5. Configured fleet server (ubuntu) so that the Windows server could enroll into it for centralized management. Installed Elastic Agent on Windows.

6. Installed Sysmon onto Windows Server and confirmed the system is generating telemetry.

7. Integrated Sysmon and Windows Defender logs into Elasticsearch.

8. Setup SSH server to allow for the real-time viewing of authentication logs and installed Elastic Agent to allow querying for logs in the elasticsearch instance.

9. Created SSH brute-force alert & dashboard in Kibana to visualize where the attacks are coming from.

10. Observed Authentication logs from the Windows Server and created alerts/dashboards for SSH and RDP brute-force attacks.

11. <p>Created an <a href="https://imgur.com/a/n0oHbhF" style="color: blue; text-decoration: underline;">attack diagram</a> showing the steps once the server has been compromised and a C2 connection established.</p>

12. Setup Mythic C2 Server and installed the apollo agent.

13. Performed the brute-force attack diagram from step 11, generated Mythic agent, and established a successful C2 session from windows server.

14. Created an alert and dashboard based on the telemetry generated by Mythic in the previous step in Kibana.

15. Setup and integrated osTicket into ELK by creating an API token for proper authentication.

16. Investigated SSH/RPD brute-force attacks and Mythic telemetry generated from all activity up until this point.

17. Configured Elastic EDR to view the telemetry it generates, automatically block potential malware from being executed, and automatically isolate the host.
